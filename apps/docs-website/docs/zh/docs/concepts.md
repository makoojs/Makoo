# 核心概念

本页解释 Makoo 如何看待「在别人的网页上加功能」这件事，以及文档中反复出现的几个词。读完后再看各篇操作指南，会更容易判断该用哪个 API。

## 两段流程

一个 Makoo 项目分成两段：

```text
Node：vite.config.ts → makoo() → 开发脚本或 .user.js
                                     ↓ 脚本管理器在匹配的网页加载
浏览器：src/main.ts → createMakoo() → apply([...]) → 查找目标 → 挂载组件 / 绑定事件
```

工具链负责把应用变成脚本管理器能安装的 userscript，`@match` 决定脚本在哪些网址运行。之后的事都发生在浏览器里，由 Core 负责：在页面中找到元素，把组件放进去，在元素上监听事件，并在页面变化时处理收尾。

`@match` 匹配网址，`injectAt` / `listenAt` 匹配网址打开后页面里的元素，这是两层不同的条件。

## Core 实例

`createMakoo()` 返回一个 Core 实例。它是一个管理范围：登记在其中的组件和监听由它统一启动、查询和销毁。

- 同一个页面可以有多个实例，名称只在各自实例内有意义。
- 实例持有已注册的适配器，组件按名称选择其中一个。
- 实例共享一套 DOM 观察，所有注入的查找与失效检测都用它，不会每个功能各开一个 `MutationObserver`。

大多数脚本只需在入口创建一个实例。

## 声明与注入

`inject()` 和 `listen()` 生成的是**声明**：一份「我需要什么」的配置，本身不做任何事。声明可以写在各自的功能模块中，再集中交给入口。

声明交给 `core.apply()` 后，才成为正在运行的**注入**。注入有两种：

- **组件**：一个框架组件，加上它的附属监听。
- **独立监听**：直接属于实例的宿主监听，不依附任何组件。

每个注入都有一个**注入名称**。名称是稳定的业务标识，用来取得控制入口；它与 DOM、选择器无关。

## 独立监听与附属监听

宿主监听绑定在宿主页面的元素上，例如网站自己的按钮、视频、输入框。它不用于监听组件内部的元素，组件内部的事件请用框架自己的写法。

| | 独立监听 | 附属监听 |
| --- | --- | --- |
| 写在哪里 | 直接放进 `apply([...])` | 放进 `inject({ listeners: [...] })` |
| 属于谁 | Core 实例 | 所属组件 |
| 何时运行 | 自己启动、停止 | 组件挂载后启动，组件这一轮结束时（停止、重注入、失败或移除）一起停止 |
| 能否单独控制 | 有自己的命令入口 | 只能读取状态 |
| 目标失效后 | 按自己的 `reinject` 决定 | 按组件的 `reinject` 决定是否局部恢复 |
| 执行失败时 | 只影响自己 | 等待超时、绑定失败、恢复失败都会结束整个组件 |

选择方法很简单：这个监听离开组件还有没有意义？有，就用独立监听；它是组件功能的一部分（例如面板依赖的网站按钮），就用附属监听。

## 挂载目标与组件容器

组件通过 `injectAt` 找到的宿主元素叫**挂载目标**。Core 不会直接把组件渲染进挂载目标，而是在它的末尾追加一个专用的**组件容器**，组件只挂在容器里。

这样做有两个好处：宿主原有的内容不会被框架覆盖；卸载时只需移除容器，不用分辨哪些节点是自己加的。

## 适配器

Core 不依赖任何框架。**组件适配器**负责具体的框架挂载与卸载，并把命令和状态交给组件。`@makoojs/vue` 和 `@makoojs/react` 各提供一个，名称分别是 `'vue'` 和 `'react'`。

适配器需要显式注册，组件也要显式写出 `adapter: 'vue'`。Makoo 不根据组件形状或文件后缀猜测框架，所以同一个实例里可以同时使用 Vue 和 React 组件。

## 命令入口与状态入口

每个顶层注入对外提供两个入口：

- **命令入口**：`start()`、`stop()`、`remove()`，表达「我希望它运行 / 停止 / 消失」。
- **状态入口**：只读的当前状态，可订阅，并附带最近一次错误 `lastError`。

把控制和读取分开，是为了让只关心状态的代码（例如显示指示灯）不会误触控制，也让只发命令的代码（例如关闭按钮）不必订阅状态。

入口通过名称取得：外部代码用 `core.injection(name)`、`core.injection(name).statusHandle`，组件内用框架 API。设置页、快捷键模块不需要入口模块把变量层层传进来。

入口绑定的是**那一个注入**，而不只是名称。注入被移除后，旧入口不会转而控制之后登记的同名注入。

## 状态只表达可用性

组件状态是 `idle`、`waiting`、`mounted`、`failed`，监听状态是 `idle`、`waiting`、`bound`、`failed`。它们只回答一个问题：这个功能现在能不能用？

宿主页面上发生的点击、播放等**业务事件**不是状态。事件触发时监听状态仍是 `bound`，业务逻辑在事件处理函数里完成；需要通知组件时，通过共享的业务数据或函数传递。

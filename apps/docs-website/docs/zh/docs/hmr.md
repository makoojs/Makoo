# 热更新

开发时修改代码后，浏览器里的脚本怎样更新？简短的回答是：Makoo 不处理热更新，全部交给 Vite 和框架插件。本页解释这为什么足够，以及唯一需要你自己清理的情况。

## 默认会发生什么

| 修改内容 | 更新方式 |
| --- | --- |
| Vue 单文件组件 | `@vitejs/plugin-vue` 在组件内就地更新，不重新运行入口 |
| 只导出组件的 React 模块 | React Fast Refresh 就地更新，不重新运行入口 |
| 导出了非组件内容的 React 模块 | 更新沿依赖链传到入口，整页刷新 |
| 入口 `main.ts` 或它导入的普通模块 | 整页刷新 |
| 样式 | 由 Vite 或框架插件更新样式 |

整页刷新时，旧页面连同旧的 Core 实例、组件、事件绑定一起被浏览器销毁，开发脚本在新页面中重新运行，只会有一个新实例。组件就地更新时，入口不会重新执行，`createMakoo()` 也不会再被调用。

因此在默认流程下，不会出现「热更新后组件挂载两次」的情况，入口中也不需要写 `import.meta.hot.dispose()`。即使写了，入口不是热更新边界，这个回调也不会被调用。

## 为什么入口更新会刷新整个页面

Vite 收到文件变化后，会沿着导入链向上寻找能接受更新的模块。入口没有导入者，自身也不接受更新，于是 Vite 通知浏览器整页刷新。

在开发模式下，`vite-plugin-monkey` 让脚本先加载 Vite 客户端，再加载你的入口。所以这次刷新刷新的是宿主网页本身：旧页面上的一切随之结束。

## 自定义热更新边界

只有一种情况需要你自己清理：你主动写了 `import.meta.hot.accept()`，并且在这个模块中创建了 Core 实例。此时更新会停在这个模块，模块重新执行时会创建第二个实例，而旧实例仍在运行。

这种情况下，请在同一个模块中销毁旧实例：

```ts
import { createMakoo } from '@makoojs/core';

const core = createMakoo();
// ...useAdapter、apply

if (import.meta.hot) {
  import.meta.hot.accept();
  import.meta.hot.dispose(() => core.dispose());
}
```

Makoo 不会替你生成这段代码。建议把 `createMakoo()` 和 `apply()` 放在普通的入口模块中，让默认的整页刷新处理更新。

## 配置和依赖变化

安装或升级依赖、修改 `vite.config.ts` 后，观察 Vite 是否自动重启；需要手动重启时，在开发终端按 `r`。修改 `@match` 等脚本元信息后，还要确认脚本管理器中的开发脚本已经更新，见[本地开发](./development.md)。

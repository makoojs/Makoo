# @makoojs/cli

## 0.3.1

### Patch Changes

Move `@makoojs/core` to a consumer-provided peer dependency for the CLI and framework adapters.

`@makoojs/cli`, `@makoojs/vue`, and `@makoojs/react` now expect Makoo projects to install `@makoojs/core` explicitly, while keeping it as a workspace dev dependency for local package development. This avoids installing a nested copy of core when downstream projects already declare their own core dependency.

The create-makoo templates now recommend the aligned Makoo package versions for generated projects.

## 0.3.0

### Minor Changes

`@makoojs/cli` now generates runtime entries using the new Makoo runtime API from `@makoojs/core`.

Generated code no longer creates or runs an `Injector` instance. Instead, the CLI now creates a Makoo runtime with `createMakoo()`, declares tasks with `inject()` / `listen()`, and starts them with `makoo.start(...)`.

CLI-facing injector default types and internals have been renamed to match the manifest contract:

- `InjectorConfig` → `InjectionDefaults`
- `ResolvedInjectorConfig` → `ResolvedInjectionDefaults`
- `DEFAULT_INJECTOR_CONFIG` → `DEFAULT_INJECTION_DEFAULTS`
- `resolveInjectorConfig()` → `resolveInjectionDefaults()`

The manifest field remains `injectionDefaults`:

The virtual entry generated by the CLI now:

- imports `createMakoo`, `inject`, and `listen` from `@makoojs/core`
- creates a Makoo runtime with the resolved adapters and defaults
- builds a task declaration list
- starts the generated tasks with `makoo.start(makooTasks)`

This keeps generated code aligned with the new declaration-based core runtime.

## 0.2.0

### Minor Changes

- 10646e4: Improve the `makoo inspect` output by grouping resolved project, source, runtime, monkey, injector, injection, and framework data into clearer sections.
